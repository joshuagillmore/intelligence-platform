## Open — needs a decision, not a fix

1. **URL and Domain nodes dominate the graph.** 2,653 of 5,258 entities are
   URLs; 4,645 entities are isolated. Fix #4 stops them crowding the graph view,
   but does not decide whether they should be created.
2. **The Cyber IOC table lists source domains as indicators.** `bbc.com`,
   `apps.apple.com`, `chromewebstore.google.com` appear under "54 Unrated —
   Needs triage". These are the sites the crawler read, not indicators of
   compromise. Same root as (1), but this is where it does real harm.
3. **The Cohere key is a trial key**, rate-limited to 20 calls/minute. Topic
   naming needs ~31 and every call fails. Topic labels will stay keyword-derived
   until the key is upgraded or that work is pointed at the local Ollama. Not
   fixable in code — fix #7 and #12 make it visible rather than silent.

## The pattern worth naming

Seven of the twelve are the same shape: **a failure or absence rendered as a
plausible value.** A cache that never hits looks like a slow endpoint. A missing
`connections` field plus `|| 0` looks like a map with no connections. A
rate-limited provider looks like an unconfigured one. Truncation at 50 looks
like a project with 50 entities. None of them raises an error, and none would
fail a smoke test asserting 2xx.

This extends the two defect classes already recorded for this codebase
(success-shaped zeros; parsing model output by the shape you asked for). The
common defence is the same: **when a value can mean "nothing" or "unknown", say
which** — a reason field, a total, a provenance label, a declared omission.

## Notes for whoever runs the suite next

Running two pytest processes against the same Neo4j deletes each other's
fixtures — the teardown removes every `test-*` project. It cost me one false
failure. Also: a test that creates a `:Project` node without a `project_id`
property leaks permanently, since the teardown keys on that property.
