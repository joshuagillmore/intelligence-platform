Token adherence

A token only holds if it is the single way to express its value. Where a colour is also written inline, the token stops being canonical — and the theme stops being changeable in one place.

The rule

Do
className="bg-navy-800
  border border-navy-600"
Don't
style={{ backgroundColor:
  '#1a1f2e' }}

The specific problem

The app has two border greys: #313849 (the navy-600 token) and #2f3444 (undeclared, 43 uses). They differ by rgb(-2,-4,-5) — invisible on screen, but two separate values to maintain. Nobody chose that; it accreted.

The cost is not aesthetic. With the surface colour written inline in 33 places and an undeclared grey in 43 more, the theme cannot be changed from tailwind.config.ts — a re-theme becomes a 76-site edit. Consolidating to navy-600 and the token classes makes the config authoritative again.
