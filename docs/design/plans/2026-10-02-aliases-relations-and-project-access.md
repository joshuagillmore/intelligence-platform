## Cross-package contracts

1. **Access model (P → F).** Roles: `owner` (full control, can manage members and delete), `editor` (read and write project data), `viewer` (read only). An admin user (`role == "admin"` on the session) has implicit `owner` on every project and is not listed as a member. The creator of a project becomes its `owner`. A project with no members at all (every pre-existing project) is readable and writable by every authenticated user until someone adds a member, and the response says so (`access: "open"`); the first member added must be an owner, which closes it. This keeps existing single-analyst deployments working unchanged.
2. **Enforcement (P).** `require_project_access(min_role)` is a FastAPI dependency resolving `project_id` from the path, the query string, or a JSON/form body field named `project_id`; it returns 403 with `detail: "No access to this project"` (never 404, which would leak existence) and 404 only when the project does not exist. Every route that takes a project id uses it; routes that take an entity, document, plan or PIR id resolve the owning project first and check that. Project list routes return only accessible projects. Admin routes are unchanged.
3. **Member routes (P → F).** `GET /projects/{id}/members` → `{members: [{username, role, added_by, added_at}], access: "open" | "restricted", my_role}`; `PUT /projects/{id}/members/{username}` body `{role}` (owner only; the first member must be an owner); `DELETE /projects/{id}/members/{username}` (owner only; cannot remove the last owner, 409). `GET /projects` and `GET /projects/{id}` gain `my_role` and `access`.
4. **Entity degree (A → F).** `GET /entities` items gain `relationship_count: int` (degree over analytic edges, excluding Document MENTIONS); the cyber page's "relations" column reads it.
5. **Location aliases (A).** `Location` gains `aliases: list[str]`; the government↔country rule stores the written government form as an alias on the country node (extraction merge and graph-build resolution); `resolve_entity_name` and `search_entities(query=...)` match aliases as well as names.
