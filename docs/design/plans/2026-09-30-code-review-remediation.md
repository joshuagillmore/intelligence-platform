# Code Review Remediation (2026-09-30) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One worker per work package, each in its own git worktree, each with its own Neo4j. The lead integrates packages serially onto `fix/code-review-2026-09-30`.

**Goal:** Fix the findings in `docs/code-review-2026-09-30.md` (the spec for this plan) so that the platform stops turning failures into plausible values, guards what it claims to guard, and ships the image it tests.

**Architecture:** The findings span every layer, so the work is partitioned by *file ownership*, not by review area: nine packages, no two of which edit the same file. Where a fix changes a contract that another package consumes, the contract is fixed in the "Cross-package contracts" section below and both sides implement against it without waiting for each other. Each package is TDD per finding (a failing test that reproduces the finding, then the fix), commits per finding or per tight group, and runs the full definition-of-done checks before reporting.

**Tech Stack:** Python 3.11 / FastAPI / Neo4j (sync driver) / SQLAlchemy async / pytest; Next.js 14 App Router / TypeScript / vitest / Playwright; Docker / Railway / GitHub Actions.

**Spec:** `docs/code-review-2026-09-30.md`. Finding IDs below (A-1, G-6, "Low → C") refer to that document. Each finding there carries file:line, a failure scenario, and a one-sentence fix; this plan does not repeat them.

## Global constraints

- Never commit to `main`; every package branches from `fix/code-review-2026-09-30`.
- Definition of done is unchanged: backend `uv run ruff check .` **and** full `uv run pytest` against the package's own Neo4j; frontend `npm run lint` **and** `npm run build` **and** `npm run test`.
- LLM provider selection lives only in `llm/providers.py`. LLM output is read only through `services/llm_output.py` helpers.
- Every new setting goes in `Settings` **and** `.env.example`.
- No new heavy dependencies. `to_thread`, not new frameworks, for blocking work.
- Do not refactor beyond the finding. Do not touch files outside your package's ownership list; if a fix genuinely needs one, stop and report it instead.
- Every test must fail before the fix and pass after. A test that asserts the requested LLM shape only is not a test of a parser: include a bolded, a numbered, a table-row and a prose-prefixed fixture.
- Commit messages: `fix(<area>): <what, in plain words>` with the session attribution trailer.

## Review focus (inputs the spec implies but no finding's test pins)

1. A model reply that is *entirely* prose with no label at all: every labelled-value parser must return its fallback **and** a `parsed: false` signal, never a partial match. (WP-E `llm_output` tests.)
2. A Neo4j that goes away mid-request: every route that now runs the store in `to_thread` must still return a 503, not hang the loop or leak a thread. (WP-A health test with a dead driver.)
3. A redirect chain ending on a *public* host after passing through a private one: the crawler must reject the whole result, not just the final URL. (WP-D crawler test with a two-hop fake.)
4. A `JWT_SECRET` of exactly 31 bytes and one of 32: the boundary must be tested on both sides. (WP-A.)
5. A frontend response that is *both* shaped correctly and empty (e.g. `{watched_entities: [], count: 0}`): pages must render the true empty state, not the error state. (WP-G.)

## Cross-package contracts

Both sides implement against these; neither waits for the other.

1. **Relationship direction (B → A, F, H).** `GraphStore.get_relationships(entity_id)` and `get_relationships_bulk` return `source_id`/`source_name` as the *true* start node and `target_id`/`target_name` as the true end node (`startNode(r)`/`endNode(r)`), plus `direction: "out" | "in"` relative to the queried entity. Every existing key is kept.
2. **Subgraph scoping (B → A, F).** `get_subgraph(entity_id, hops, project_id=None)` and `find_shortest_path(..., project_id=None)` clamp `hops` to 1..4, add `LIMIT 5000` paths, and when `project_id` is given require every non-catalog node on the path to have that `project_id`; catalog labels (`AttackTechnique`, `AttackGroup`, `AttackSoftware`, `AttackTactic`, `AttackMitigation`, `Cwe`, `Capec`, `D3fendTechnique`) may appear only as path endpoints. A passes `project_id` from `query.py` and `entities.py`; F passes it from the MCP tool.
3. **Graph cache (B → A).** `graph_cache.get_or_build_graph(project_id, build_fn)` is reserved for the analytics build (`_build_networkx_graph`, limit 10000). `GET /graph` (A) must build its display graph without touching `graph_cache`. `GraphStore.get_full_graph(project_id, limit)` orders nodes and edges deterministically (`ORDER BY` degree desc, then id) and returns `truncated: bool` alongside `nodes`/`edges`. A passes `truncated` through on `/graph`; H shows a "showing N of M" note when it is true.
4. **`/graph` edge payload (A → H).** Each edge carries `source`, `target`, `type`, `confidence`, `evidence` (str), `method` (str), `source_doc_id` (str), `polarity`, `first_seen`, `last_seen`.
5. **LLM unavailable on products (E → G).** `POST /reports/generate`, `POST /assess/generate` and `POST /assess/probability` raise `HTTPException(503, detail="LLM provider unavailable")` when no provider can be reached or generation fails. They never return 200 with error text as `content`. G's pages treat the error path as the failure state (products page must never store it in history).
6. **`/query` degraded answer (A → G).** When the LLM fails, `POST /query` returns 200 with `answer: ""`, `model: "none"`, `llm_error: "<sanitised reason>"`, and `context` as today. G renders a degraded notice ("No model ran; showing retrieved context") and marks the message failed; it must not show `context` as the answer.
7. **Topic summary stream (E → G).** `GET /topics/.../summary` (whatever the current path is; do not rename) emits SSE where every `data:` payload is a JSON string: `data: "## Key actors\n- APT29"\n\n`. Terminal event: `data: [DONE]\n\n`. Error: `data: {"error": "Summary generation failed"}\n\n` with no exception text. Cache hits are emitted the same way. G buffers across reads, splits on `\n\n`, `JSON.parse`s the payload, and appends.
8. **Watchlist (G, H).** Backend shape is unchanged: `{watched_entities: [...], count}`. All four consumers read exactly that.
9. **Centrality (G).** `/graph/centrality` keeps `degree`; the dashboard reads `degree` and normalises by the max in the list.
10. **Timeline (E → G).** `/timeline` orders by `coalesce(event_datetime, created_at) DESC` server-side, returns `events`, `count` (page), `total` (true count), `truncated`, and `types_present: [str]`. G builds the type filter from `types_present` and shows `count of total`.
11. **Search totals (A → G).** `/search` returns `results`, `count`, `total` (true match count), `truncated`. G shows "N of M" and corrects the copy to "matches entity names".
12. **Enrichment GET on miss (F, G).** `GET /enrichment/entities/{id}` returns only providers with a non-null payload (`{}` on a full miss). G also drops null payloads defensively.
13. **Personas (A → G).** Create/update/delete/activate require admin; POST with a built-in id returns 409. G surfaces errors via the notification provider.
14. **Ollama errors (C → A, E, D, F).** `OllamaProvider.generate`/`stream` raise `LLMProviderError` (new, in `llm/base.py`, subclass of `RuntimeError`) on non-2xx or an `error` key. Callers already wrap generation in `try/except Exception`; they must not catch it silently where the spec says the failure must surface.
15. **Blocking store calls (B → A, D, E, F).** `build_graph_from_extractions` stays sync. Every async caller wraps it in `asyncio.to_thread`: A (`ingest.py`), D (`agentic.py`, `runner.py`), E (`collection_plans.py` upload), F (`mcp/server.py`). Same for `extract_entities_nlp`, `process_file` and any `GraphStore` call inside an async handler in those packages.
16. **`Relationship.project_id` (B → A, F, E).** `models/relationships.py` gains `project_id: str = ""`. `create_relationship` uses it for a labelled, indexed match when present. Callers that construct `Relationship` pass `project_id`.
17. **Graph-build attribute validation (B → C, D).** `build_graph_from_extractions` validates LLM attributes field by field, drops and logs invalid ones, and its result dict gains `dropped_attributes: int`. It never raises `ValidationError` for an attribute.
18. **JSON parsing (E → C, D, F).** `llm_output.json_object(text) -> dict | None` is the only JSON-from-model parser. E adds `llm_output.normalise_line(line) -> str` (strips `*`, `_`, backticks, leading list/numbering markers and table pipes, collapses whitespace) for line-oriented parsers. C, D, F replace their fence-split + `json.loads` with `json_object`.
19. **CSP (G → A).** G sets `Content-Security-Policy` via `headers()` in `next.config.mjs` (policy derived from the hosts `GeoMap.tsx` and the basemap switcher actually use; `img-src 'self' data: blob:` plus tile hosts; `frame-ancestors 'none'`). A's frontend proxy in `app.py` forwards upstream response headers (all except hop-by-hop) so the header reaches the browser on Railway.
20. **Settings (A).** `jwt_secret`, `encryption_key`, `cors_origins` become `Settings` fields; `model_config` gets `extra="ignore"`; `env_file` resolves relative to the repo root via `__file__`. Other packages keep reading via `settings.<field>`.
